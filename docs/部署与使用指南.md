# OpenMAIC 是怎么做的（完整实操手册）

本文回答一个问题：**本机的梵语 AI 课堂是怎么从零搭起来的，以及 OpenMAIC 是怎么运作的。** 全部内容基于 2026-10-14 在 Windows 桌面实际部署与生成课堂的验证记录；任何 Agent 按此手册都能复现或维护这套环境。

## 1. OpenMAIC 是什么

OpenMAIC（Open Multi-Agent Interactive Classroom，清华 THU-MAIC，MIT 协议）是一个开源 AI 互动课堂平台：输入一个主题或教材，AI 自动生成完整课堂——幻灯片讲解（AI 教师语音+聚光灯/白板）、交互式模拟、测验（AI 判分）、项目制学习（PBL），课堂中有 AI 教师和 AI 同学智能体与你实时讨论。

- **版本**：v1.2.0-rc.2（服务端优先：课程生成在服务端常驻进程运行，关页面不中断；必须 PostgreSQL 存储）
- **技术栈**：Next.js 16（React 19 / TypeScript 5）、LangGraph 多智能体编排、pnpm workspace、Tailwind 4
- **模型**：服务商中立，通过 `openmaic.yml` 配置 provider + 槽位（slot）

## 3. 从零部署 SOP（本机验证过）

### 3.1 前置与克隆

```bash
# 环境：Node >= 22.19、pnpm >= 10、git。PostgreSQL 16（本机无 Docker，用原生 PG）
node -v && pnpm -v

# 中国大陆直连 github.com 会被屏蔽（DNS 解析到 127.0.0.1），用镜像前缀克隆：
git clone https://ghfast.top/https://github.com/THU-MAIC/OpenMAIC.git <短路径>/OpenMAIC
# 备用镜像：gitclone.com / ghproxy.net / gh-proxy.com（ghfast.top 实测可用）
```

> 克隆位置务必选**短且无空格**的路径（如 `C:\OpenMAIC`）。教训：先克隆到 agent 工作目录（路径含 `User Data\Default\...` 空格+超长）导致 Turbopack/webpack 编译双双失败（踩坑#1）。

### 3.2 安装依赖

```bash
cd OpenMAIC
pnpm install --registry=https://registry.npmmirror.com
# 首次约 20 分钟（2500+ 包 + workspace 子包构建）。本机曾出现
# ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY：非交互环境需先 $env:CI='true'
```

### 3.3 配置（两件套）

**`.env.local`**（复制自 `.env.example`，填必需项）：

```env
# 模型 Key（用哪家服务商就填哪家；本次用 MiniMax Token Plan 一个 Key 覆盖对话/图像/TTS/搜索）
MINIMAX_API_KEY=<你的 MiniMax API Key>            # 你的 Key，勿外泄
MINIMAX_MODELS=MiniMax-M2.7,MiniMax-M3

# PostgreSQL（必填，缺失则服务拒绝启动）
DATABASE_URL=postgres://openmaic:<YOUR_DB_PASSWORD>@127.0.0.1:5432/openmaic

# 单用户模式：所有访问者共用一个课程库（本机个人部署，避免换浏览器看不到课堂）
OWNER_SINGLE_USER=true
```

**`openmaic.yml`**（复制自 `openmaic.example.yml`，声明服务商与槽位）：

```yaml
providers:
  minimax:
    preset: minimax
    apiKey: ${MINIMAX_API_KEY}        # Key 留在 .env.local，用 ${VAR} 引用
    models: [MiniMax-M2.7, MiniMax-M3]

slots:
  llm: minimax:MiniMax-M3             # 默认对话/大纲/讲解模型
  course.content: minimax:MiniMax-M3  # 场景内容生成（交互场景必须用强模型，见踩坑#2）
  image: minimax                      # 配图（Token Plan 默认模型）
  tts: minimax                        # 语音讲解
  webSearch: minimax                  # 联网搜索
  # video: null                       # 视频生成默认关（M Plan 不含视频）
```

槽位机制：`slots` 下每个键是一处用 AI 的位置（大纲、幻灯片内容、语音、搜索…），值为 `服务商:模型ID`；只写服务商 ID 表示用该套餐默认模型。写进文件的槽位是服务端默认值，用户可在网页「设置→模型服务」里改（除非配置 `lock`/`allowUserKeys: false`）。服务启动时校验该文件，语法错误会指出行号。

### 3.4 数据库

本机无 Docker，用 winget 原生安装 PostgreSQL 16：

```powershell
winget install PostgreSQL.PostgreSQL.16    # 无人值守，安装时设 super 密码
# 服务 postgresql-x64-16 自动注册为 Windows 服务（Running）
# 建角色与库：
& "C:\Program Files\PostgreSQL\16\bin\psql.exe" -U postgres -c "CREATE ROLE openmaic LOGIN PASSWORD '<YOUR_DB_PASSWORD>';"
& "C:\Program Files\PostgreSQL\16\bin\psql.exe" -U postgres -c "CREATE DATABASE openmaic OWNER openmaic;"
```

### 3.5 启动与验证

```bash
cd C:\OpenMAIC && pnpm dev    # 首次编译 30–60 秒；日志看控制台
```

验证（全部通过才算部署成功）：

```
GET http://localhost:3000/            → 200，页面标题 OpenMAIC
GET http://localhost:3000/api/health  → {"success":true,"status":"ok","version":"1.2.0-rc.2",...}
GET http://localhost:3000/api/server-providers → minimax 出现且 models 列出 M2.7/M3
```

## 4. 课堂生成机制

### 4.1 两阶段流水线

1. **大纲生成**（outline）：AI 分析 requirement（+材料），产出结构化课堂大纲
2. **场景生成**（scene content）：每个大纲条目生成一个场景——幻灯片 / 测验 / 交互模拟 / PBL；同时为每个场景生成动作脚本与 TTS 语音

全部在服务端运行（PostgreSQL 记录 run 状态，进程崩溃可续跑），关浏览器不中断。进度以百分比呈现，18 场景全程约 10 分钟。

### 4.2 API 契约（命令行/脚本调用）

```
POST /api/generate-classroom       提交生成
  body: { "requirement": "教学要求文本", "materialIds": ["mat_..."] }
  成功 → 202 { jobId, runId, status:"queued", pollUrl, pollIntervalMs }

GET /api/generate-classroom/{jobId}  轮询进度
  status: queued → running（step: researching/generating_outlines/generating_scenes）→ succeeded/failed
  失败：error 字段说明原因 + retryable:true → 用 retry 续跑

POST /api/generation-runs/{runId}/retry   失败暂停后续跑
  body: { "commandId": "新uuid" }

POST /api/materials                     上传教材（原始字节体，非 multipart）
  headers: content-type=application/pdf, x-material-filename=文件名
  返回 201 { materialId, extraction:{status:"extracting"} }；上传即后台提取

GET /api/materials/{id}                 查提取状态（extracting → 完成）
```

**关键细节：owner（所有者）隔离。** 未设单用户模式时，每个浏览器 cookie 对应一个 owner，课程互不可见；API 调用需先 GET `/` 拿 owner cookie 并复用同一 cookie（持久化到文件），否则跨进程查询返回 404。**本机已设 `OWNER_SINGLE_USER=true` 规避此问题。**

### 4.3 生成脚本

`scripts/generate_classroom.py` 封装了全流程（cookie 暖启动→上传教材→提交→轮询→交付），直接传 `--requirement` 即可。

## 5. 踩坑记录（决定成败，别重蹈）

| # | 坑 | 现象 | 根因与解法 |
|---|---|---|---|
| 1 | **路径含空格+超长** | Turbopack 报 `Cannot depend on path (\\?\C:\...) outside of root directory`；webpack 报 `Module not found: Can't resolve 'fs'` 等 Node 内置模块解析失败 | 项目放在 `User Data\Default\.doubaowork\...`（空格+超长）导致模块解析越界。**解法：整体迁移到 `C:\OpenMAIC` 短路径**。迁移用 Move-Item 会在 pnpm junction 上失败并留下半成品，别硬删 node_modules（junction 删除会卡死），用 `Rename-Item` 把旧目录改名 `.bak` 绕开，再重新 `pnpm install` |
| 2 | **弱模型生成交互场景失败** | 生成到某 interactive 场景反复失败暂停：`StepRefusal: Failed to generate content: 元音发音互动练习`（日志见 `[ERROR] [GenerationRun] Failed to generate content`） | MiniMax-M2.7 输出的交互场景（含 HTML/结构代码）过不了校验，内部重试 6 次仍失败。**解法：`openmaic.yml` 的 `llm`/`course.content` 改用 `MiniMax-M3`，重启后 `retry` 即通过** |
| 3 | **cookie 隔离致课堂"消失"** | 脚本生成的课堂在用户浏览器打不开/看不到 | 匿名模式下课程按 cookie 分 owner。**解法：`OWNER_SINGLE_USER=true`**（改 `.env.local` 后重启） |
| 4 | **Watchpack 全盘扫描拖卡系统** | dev server 运行时 PowerShell 连续超时、系统卡死 | 长路径下的 webpack dev 会扫描 C:\ 根。迁移短路径后消失；另注意删除 node_modules 时 `cmd rmdir /s /q` 会卡在 junction（"directory is not empty"刷屏），**用重命名 `.bak` 代替删除** |
| 5 | **pnpm 非交互删除拒绝** | `ERR_PNPM_ABORTED_REMOVE_MODULES_DIR_NO_TTY` | `$env:CI='true'` 后重跑 install 即可 |
| 6 | **git 元数据随移动损坏** | `git status` 显示 `No commits yet` | 不影响运行，别依赖该仓库 git 历史；需要时可从镜像重新 clone |

## 7. 常驻化建议

当前以 `pnpm dev` 前台/后台方式运行，重启电脑后需手动拉起。用户偏好正规常驻：推荐创建 **Windows 计划任务**（开机/登录自启，`pnpm start` 生产模式更稳），或注册为 Windows 服务（如 NSSM 包装 `next start`）。生产模式需先 `pnpm build`（本机短路径下可行）。注意：计划任务需在 `.env.local` 同目录下启动，环境变量随任务配置。
